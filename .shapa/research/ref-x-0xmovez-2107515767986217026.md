## Findings

The photo is a "research note" card titled **"Anthropic Designer (ex. Meta)"**, byline "Meaghan Choi — Claude
Code & Cowork," crediting the prompt to @0xCarnagee and stating the wording is theirs, drawn from Choi's public
talks (Behind the Craft, Product School, Dive Club), not written or endorsed by her. The card is a full
XML-tagged prompt for turning a topic into a 30-90 s **explainer film** (not a brand showreel) with sound,
burned-in captions and a re-renderable source. It is a different genre from the showreel course already
studied, but several parts generalise.

### What's genuinely new

- **Story arc by percentage of runtime**: Question (0-10%, open on the belief viewers get wrong), Model
  (10-35%, build the smallest correct picture, one element per beat), Proof (35-75%, run the model on a real
  case), Turn (75-90%, change one variable and show the consequence), Payoff (90-100%, return to the opening
  image, now read correctly, plus one next step). This is a narrative shape, not covered in
  [[motion-course]] or `principles.md`.
- **Per-scene spec fields**: ID + time range, Teaches (the one thing this scene adds), Frame (what's on
  screen and in what order of importance), Motion (enter/key action/settle/exit), Words (on-screen text ≤ 8
  words/line, plus a separate voice line), Sound (the cue marking the key action), Check (what the viewer can
  now say that they couldn't before). The Check field is a sharper per-shot quality gate than anything in
  `principles.md`.
- **Copy rule**: never put the full voice line on screen — on-screen words are anchors, not a transcript; max
  two lines on screen at once; one name per thing, used every time; every number traces to a source file or it
  is cut.
- **Accessibility is a named gate**: contrast ≥ 4.5:1, captions burned in and shipped as `.srt`, color is never
  the only signal, no flashes above 3/s, and a reduced-motion cut that keeps the same sequence of ideas. This
  is absent from `principles.md` and from the R1-R14 rule set entirely.
- **Sound numbers**: tempo-locked procedural bed with one motif that returns on the key idea, soft UI cues only
  on actions that carry meaning, bed ducks under voice, about -16 LUFS integrated, true peak at most -1.5
  dBTP, checked muted and checked audio-only.
- **Render contract, worded almost identically to our own**: `window.seek(t)` paints the frame at time `t`,
  one object holds every beat/move/cue, seeded randomness only, headless Chrome steps `t = n/60` into ffmpeg
  (libx264, crf 16, yuv420p). This matches `techniques/master-clock.md` closely enough to read as confirmation,
  not new information — except for one check this prompt adds and we don't have: **render the same frame twice
  and diff it; it must come out identical.** That is a cheap, concrete test of "pure function of time" we don't
  currently run.
- **Continuity as object transformation, not just a carried mark**: "keep objects alive across scenes and
  transform them instead of replacing them: a dot becomes a node, a label becomes an axis." Our
  `techniques/through-line.md` already carries a mark scene to scene; this sharpens it — the mark should change
  what it *means* at each stop, not just persist visually.
- **A verification checklist**: a still frame at every beat read at 390 px wide (phone-width legibility), watch
  the cut muted, then listen to it audio-only, a design-review subagent that asks review questions, an
  accessibility pass, and every fix shipped with a before/after frame pair. `principles.md` has no QA checklist
  at all today; the closest existing material is the critique-rounds note in [[motion-course]] (status column),
  which is about round count, not these specific checks.

### A tension worth flagging, not a rule

The prompt's visual system **bans** "neon glow, stock 3D blobs, gradient title cards, floating particles, fake
metrics." Two of our existing library entries are built on exactly the banned families:
`techniques/particle-flow-sphere.md` and `techniques/voxel-ripple-3d.md` (a 3D block field, which reads close
to "stock 3D blobs" in spirit if not in letter). This prompt is written for *explainer* films anchored to real
product screenshots, where generic 3D/particle motion reads as filler over a real screen recording; our showreel
and brand films are a different genre where a particle sphere or a voxel field is the one shot "only code can
do." Read as in tension, not as a reason to drop either technique — worth the operator's eye if social-studio
ever takes on an explainer-style brief.

## Principles

What generalises past this one prompt, to every social-studio video regardless of genre:

1. Accessibility is not currently gated anywhere in this project; captions, contrast, flash limits and a
   reduced-motion path are cheap and currently absent.
2. A determinism self-test (render frame N twice, diff, must match) is a free correctness check for the
   "pure function of time" claim every canvas/3D scene already makes.
3. On-screen text and voice-over are different channels with different jobs — captions anchor, they don't
   transcribe.
4. A through-line mark should earn its reappearance by changing meaning at each scene, not just persisting
   visually.
5. A verification pass belongs at three distinct senses — read at phone width, watched muted, heard
   audio-only — plus a design-review and an accessibility pass, each fix proven with a before/after frame pair.
6. A numeric loudness target (~-16 LUFS integrated, ≤ -1.5 dBTP true peak) is a concrete, checkable audio gate
   social-studio's sound step doesn't currently state.

## Techniques

No new shot-level technique entries are proposed from this reference — it is a prompt and a narrative/QA
discipline, not a shot. One existing entry is strengthened:

- **through-line** (existing, `techniques/through-line.md`): add that the carried mark should be reinterpreted
  at each stop (a dot becomes a node, a label becomes an axis), not only repositioned. Build: unchanged (DOM/
  canvas/three.js element with stable identity across GSAP timeline labels); the new requirement is that its
  role/label changes with the scene, which is a content note for whoever adapts the technique, not a new build.
